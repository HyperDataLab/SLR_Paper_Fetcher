# Find A Defensible SAFFRON Taxonomy Model

The current evidence does not identify a verified public taxonomy model suitable for completing the SLR Paper Fetcher’s SAFFRON TAXO stage. The pinned container has no `/opt/saffron/models/default.json`, and the pinned pipeline reads that configured file directly when it builds a taxonomy. SAFFRON’s trainer is supervised: it needs terms, document-term links, and gold `.taxo` relations. The checkout has one fully matched Food benchmark bundle, but no evidence that a model trained on it would be appropriate for research-paper taxonomies. TExEval’s Science files are gold evaluation taxonomies without matching Saffron term and document-term artifacts. The official v4.0 release has no uploaded model asset: its release API returns an empty `assets` array, and the page’s two links are generated source archives. This resolves the release-asset question, though checks of one pinned container/source snapshot do not establish what every SAFFRON distribution contains. ([v4.0 release API](https://api.github.com/repos/insight-centre/saffron/releases/tags/v4.0), [v4.0 release page](https://github.com/insight-centre/saffron/releases/tag/v4.0))

## TAXO loads a trained model during each run

At the pinned revision, the CLI defaults the model path to `${saffron.home}/models/default.json` and deserializes that file into SAFFRON’s `Model` before taxonomy search. The inspected container’s models directory held the English POS tagger and lemmatizer, but no `default.json`; this establishes the state of this pinned image, not every SAFFRON distribution. The README says first execution downloads required models, but it neither names a taxonomy classifier nor gives a `default.json` URL, so that generic note does not demonstrate that the classifier is provisioned automatically. ([Pinned README](https://github.com/insight-centre/saffron/blob/bcf009f176713ced1d707324043124670827125b/README.md), [pinned SaffronPipeline.java](https://github.com/insight-centre/saffron/blob/bcf009f176713ced1d707324043124670827125b/run/src/main/java/org/insightcentre/nlp/saffron/run/SaffronPipeline.java))

The runner’s current behavior is therefore consistent with source: it can return `PARTIAL` term results without TAXO, and it only invokes the pipeline when the model file passes its JSON check. The release uncertainty is now resolved: GitHub’s API reports `assets: []` and returns source archive URLs, while the two links shown on the release page are those generated archives rather than uploaded classifier assets. This rules out an uploaded model in tag `v4.0`, but does not rule out a separately distributed model or a model included in another SAFFRON package. ([v4.0 release API](https://api.github.com/repos/insight-centre/saffron/releases/tags/v4.0), [GitHub Releases API documentation](https://docs.github.com/en/rest/releases/releases?apiVersion=latest))

## The bundled benchmarks do not close the SLR data gap

The only complete training bundle found in the pinned checkout is `food_en`: term data, document-term mappings, and a gold hierarchy. Other Science `.taxo` files are present, but the corresponding `science_en` term and document-term files are absent from that checkout. Meanwhile, TExEval provides Science gold taxonomies and term lists as evaluation material; its shared-task page describes the task as unsupervised and cautions participants against using resources that formed the gold standards. These files can inform an exploratory evaluation, but the available evidence does not establish them as representative, reviewed training labels for this SLR’s extracted paper terms. ([Pinned food terms](https://github.com/insight-centre/saffron/blob/bcf009f176713ced1d707324043124670827125b/benchmarks/data/texeval/food_en-topics.json), [pinned document terms](https://github.com/insight-centre/saffron/blob/bcf009f176713ced1d707324043124670827125b/benchmarks/data/texeval/food_en-doc-topics.json), [pinned food hierarchy](https://github.com/insight-centre/saffron/blob/bcf009f176713ced1d707324043124670827125b/benchmarks/data/texeval/food_en.taxo), [TExEval data and tools](https://alt.qcri.org/semeval2016/task13/index.php?id=data-and-tools), [SemEval Task 13](https://alt.qcri.org/semeval2016/task13/))

There is also a licensing gap: the task pages do not clearly establish the license of each taxonomy file or its underlying source taxonomy. A download being public does not by itself authorize bundling the files or distributing a model derived from them. ([TExEval data and tools](https://alt.qcri.org/semeval2016/task13/index.php?id=data-and-tools))

## A reviewed model or aligned labels are still required

The upstream `taxonomy/train` entry point accepts `-p` for terms, `-d` for document-term connections, `-t` for one or more taxonomy files, and `-c` for configuration; its example trains from the matched Food benchmark. A project-domain training package therefore needs aligned terms and document-term links from a representative corpus plus expert-reviewed `.taxo` child-parent relations over the relevant vocabulary. A supplied `default.json` could avoid retraining, but it still needs SAFFRON-version compatibility, training-domain provenance, licensing and evaluation evidence. The source does not define a universal minimum training-set size or a quality threshold. ([Pinned taxonomy/train](https://github.com/insight-centre/saffron/blob/bcf009f176713ced1d707324043124670827125b/taxonomy/train), [pinned Train.java](https://github.com/insight-centre/saffron/blob/bcf009f176713ced1d707324043124670827125b/taxonomy/src/main/java/org/insightcentre/nlp/saffron/taxonomy/supervised/Train.java))

## Conclusion

Keep the current `UNAVAILABLE_MODEL` status explicit while term extraction remains available. The next meaningful input is either a reviewed, compatible model with provenance or a representative labeled training package that can be evaluated on held-out SLR-domain relations. OpenAlex topic IDs remain a separate canonical classification source; they do not supply the supervised examples SAFFRON TAXO requires.
